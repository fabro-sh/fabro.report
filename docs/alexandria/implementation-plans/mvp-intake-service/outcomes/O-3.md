## Validation Criteria

- A single Terraform module under `terraform/` (this repo) declares every AWS resource: VPC + subnets + security groups, ECS cluster + Fargate service + task definition, ALB + target group + ACM certificate, Route53 record for `fabro.report`, ECR repository, S3 bucket (private, no public-read ACL) with two prefix-scoped lifecycle rules (30-day expiration on `<YYYY>/...` and on `feedback/<YYYY>/...`), least-privilege IAM task role, and Secrets Manager (or SSM Parameter Store) entries for `SENTRY_DSN` and `FEEDBACK_DISCORD_WEBHOOK_URL`.
- The Terraform module is consumed by a thin root configuration under `terraform/live/production/` (single environment for MVP).
- A GitHub Actions workflow builds the Docker image, pushes to ECR, and runs `terraform apply` against the production root configuration on merges to `main`; PRs trigger `terraform plan` for review without applying.
- `aws configure` lists no manually-created resources matching the service's resource group; every resource appears in the Terraform state file.
- The IAM task role grants exactly: `s3:PutObject`/`s3:DeleteObject`/`s3:GetObject` (for sidecar reads + size HEAD) on the bundle-prefix subtree; `s3:PutObject` on the `feedback/` subtree; `secretsmanager:GetSecretValue` (or `ssm:GetParameter`) on the two named secrets; nothing else.
- A security review checklist passes: 32-hex CSPRNG IDs verified; presigned PUT URL TTL ≤15 minutes; bucket has no public-read; TLS terminates at the ALB (HTTP between ALB and Fargate is acceptable inside the VPC); no AWS keys baked into the Docker image or source.
- `robots.txt` is served and returns `Disallow: /` (capability URLs must not be indexed).
- The Discord webhook URL is created out-of-Terraform in Discord's UI; Terraform manages only the secret holding it.

## Motivation

[[Decision - Service Stack]] and [[System - Service Topology]] make AWS-native-by-construction the load-bearing posture of the entire product. Without Terraform-as-single-source-of-truth, the topology drifts the moment someone clicks in the AWS console; the service stops being declarative. Production-only-for-MVP (rather than staging + prod) is a deliberate scope contraction — the library is small enough and the team is small enough that a staging-and-prod split would add ~30% of the infra ticket surface for marginal MVP value. The security-review gate validates that the load-bearing security properties (capability-URL entropy, IAM least-privilege, secrets handling, bucket privacy) actually hold in the deployed system rather than just in the cards.
